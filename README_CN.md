# Cookie Share Next

服务器地址及输入框已从插件弹窗隐藏，请在“设置 → 服务器设置”修改，未登录时也可访问。账号管理、备份管理、安全设置和服务器设置各自使用独立网页。切换服务器会退出当前登录，原服务器上的数据保留。

密钥账户和第三方登录账户均可在“安全设置”绑定其他可用登录方式。一个第三方身份只能绑定一个账户，每个账户对同一提供商最多绑定一个身份；绑定不会合并不同账户的数据。已有登录密钥时可解绑最后一个第三方身份，否则必须保留至少一种第三方登录。

创建或重置密钥会打开独立页面，可复制、下载并确认保存；密钥仅显示一次，刷新不会重复创建或重置。连接失败时显示重试入口并保留会话；读取请求每次最多等待 8 秒，网络错误或 502/503/504 最多重试一次，创建、重置等写入请求不会自动重试。

界面交互检查：安装本机 Edge 后运行 `npm run test:ui`。测试使用隔离浏览器和模拟扩展接口，不操作个人浏览器资料。

Cookie Share Next 是一个 Manifest V3 浏览器扩展，用于在**有权使用的浏览器账号与会话**之间管理加密 Cookie 桶。它不绕过登录认证、访问控制或平台规则。

> English documentation: [README.md](README.md)

## 功能

- 创建、解锁、捕获、编辑、删除和应用 Cookie 桶。
- 在 Chromium 允许扩展访问的范围内读取和恢复 HTTPOnly Cookie。
- 每个桶使用独立密码在扩展本地加密后再同步。
- 导出或导入加密的 `.csn-bucket.json` 文件，实现基于文件的分享。
- 通过兼容后端使用 GitHub、Google 或 LinuxDo OAuth 登录。
- 点击“创建密钥账户”即可注册，无需第三方账号；复制系统随机生成的密钥并确认已保存，之后输入密钥即可登录。
- 可使用官方服务 `https://cookie.nestlone.com`，也可连接兼容的自部署后端。

## 安全与隐私

登录密钥只在创建或重置时显示一次，服务端仅保存哈希。密钥不同于 Cookie 桶总密码；未绑定其他登录方式时，退出后丢失密钥将无法找回账户。仍在登录时可在设置中重置，旧密钥会立即失效。每个 IP 每分钟可尝试密钥登录 20 次、创建账户 5 次，触发限流后显示具体等待秒数。

桶密码独立于账号登录，且永不离开扩展。扩展使用 PBKDF2-SHA256 在本地派生 AES-256-GCM 密钥；服务端只保存不透明的加密信封、桶 ID、密文大小和时间戳。

服务运营者可以看到账号身份、桶数量、近似密文大小与请求时间，但不能从存储数据中解密桶名称、Cookie 域名、Cookie 值或桶密码。不同 OAuth 提供商报告相同邮箱时，账号不会自动合并。完整细节见[协议与威胁模型](docs/protocol.md)。

导出的桶文件和桶密码都是敏感信息，应通过不同的安全渠道发送。桶密码一旦分享，不能只对某一位接收者撤销；需要撤销访问时，请创建新桶并设置新密码。

## 安装扩展

项目目前以原生未打包扩展形式提供，不需要生产构建步骤。

1. 克隆仓库；如需运行测试，先安装依赖。
2. 打开 Chrome 或 Edge 的扩展管理页面。
3. 启用**开发者模式**。
4. 点击**加载已解压的扩展程序**，选择本仓库目录（本地工作区中的 `frontend/`）。
5. 打开扩展弹窗，选择 OAuth 登录、创建密钥账户或输入已有密钥登录。如需自部署后端，请先在“设置 → 服务器设置”修改 HTTPS 地址并测试连接。
6. 创建 Cookie 桶并设置高强度、唯一的桶密码。

扩展申请 `activeTab`、`cookies`、`storage`、`downloads`、`identity` 和 `scripting`，默认主机权限仅为官方后端 `https://cookie.nestlone.com/*`。首次保存或切换时，单独申请当前主机及其子域名的访问权限；自托管后端通过“连接服务器并加载登录方式”单独授权。旧账号或导入账号若包含其他 Cookie 域名，会先列出域名并等待授权，拒绝后不会清除当前登录状态。可在浏览器扩展设置中撤销访问权限。在敏感浏览器配置文件中安装前，请先审查源码。

## 使用自部署后端

后端在独立仓库维护：[cookie-share-next-server](https://github.com/nestlone/cookie-share-next-server)。请将其部署在 HTTPS 之后，并在扩展中使用该公开服务地址。密钥账户无需配置 OAuth；如需第三方登录，可另外配置 OAuth 提供商。

前端与后端有意分别维护协议测试向量和文档副本。修改协议时，必须同步更新两个仓库并运行各自的契约测试。

## 开发

要求：Node.js 22.5 或更新版本。

```bash
npm ci
npm test
node -e "JSON.parse(require('node:fs').readFileSync('manifest.json'));"
```

完整的本地集成验证需要先构建相邻的后端目录：

```bash
npm --prefix ../backend ci
npm --prefix ../backend run build
node e2e/run.mjs
```

GitHub Actions 仅验证扩展、Manifest 和加密契约；完整 E2E 仅在本地运行，以避免为独立私有后端仓库保存读取凭据。

## 目录结构

```text
.github/       前端持续集成
contract/      扩展测试使用的固定协议向量
docs/          协议与威胁模型
e2e/           本地扩展与后端集成验证
icons/          扩展图标
src/            Manifest V3 service worker、弹窗和共享模块
test/           加密与契约测试
```
